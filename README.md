# DrinkStar: сайт, онлайн-заказ, оплата, клуб, аналитика

Нужен только Node.js 22.13+ (проверено на 24). Устанавливать пакеты не нужно.

```
npm start
```

| Что | Адрес | PIN по умолчанию |
|---|---|---|
| Сайт | http://localhost:3000 | |
| Экран персонала | /staff.html | `1234` |
| Аналитика владельца | /admin.html | `0000` |

Очистить тестовые заказы и клиентов перед показом: `npm run reset`

## 1. Показ клиенту (всё готово)
Оплата и SMS работают в **демо-режиме**: деньги не списываются, SMS не отправляются (код входа показывается на экране).

Сценарий показа на двух экранах (телефон и ноутбук):
1. Телефон: «Войти в клуб» → номер → демо-код. Выбрать напитки, сироп в корзине бесплатный, оформить заказ.
2. Ноутбук `/staff.html`: заказ со звуком, меткой «★ Клуб» и «Оплачено онлайн». «Взять в работу», «Готов», «Выдан».
3. Телефон: статус меняется сам, после выдачи начисляются 5% бонусов. Следующий заказ можно частично оплатить бонусами.
4. Ноутбук `/admin.html`: выручка, средний чек, топ напитков, загрузка по часам, клуб. Кнопка «Скачать CSV».

## 2. Как работает клуб
Настройки в `data/club.json`: `cashbackPercent` (5), `maxBonusPercent` (50), `freeSyrup`.
- **Гость** заказывает без входа и платит полную цену.
- **Участник** входит по телефону и коду из SMS (новый номер сразу становится участником). Получает бесплатный сироп, 5% кэшбэка бонусами (1 бонус = 1 ₸) и может оплатить бонусами до 50% заказа.
- Бонусы начисляются, когда бариста нажимает «Выдан». Если заказ отменён или не оплачен за 15 минут, списанные бонусы возвращаются.
- Все расчёты делает сервер. Подменить цену, сироп или бонусы с телефона нельзя.

**У кофейни уже есть система лояльности.** Чтобы бонусы не расходились в двух местах, нужно решить: заменяет ли новый клуб старый или подключаемся к существующей системе (отдельная интеграция, нужна её документация).

## 3. Выложить в интернет
Готовы `Dockerfile` и `render.yaml` (бесплатный вариант для показа). Переменные окружения:

| Переменная | Что |
|---|---|
| `STAFF_PIN`, `ADMIN_PIN` | **обязательно**, разные, не `1234` и не `0000`. Иначе в боевом режиме сервер не запустится |
| `NODE_ENV` | `production` |
| `BASE_URL` | адрес сайта, например `https://drinkstar.kz` |
| `PAYMENT_PROVIDER` | `mock` (демо), `none` (только касса) или имя провайдера |
| `SMS_PROVIDER` | `demo` или имя провайдера |
| `DATA_DIR` | папка базы `drinkstar.db`. На хостинге смонтируйте постоянный диск, иначе данные пропадут при перезапуске |

**Внимание:** `SMS_PROVIDER=demo` показывает код входа прямо на странице. Допустимо для показа, но не для боевого запуска.

## 4. Подключить настоящую оплату
Нужны договор с банком/платёжной системой и ключи.
1. Скопировать `payments/_template.js` в `payments/kaspi.js` (имя по провайдеру).
2. Заполнить `createPayment` и `handleWebhook` (инструкции в комментариях файла). Провайдеру передаётся сумма к оплате деньгами, уже за вычетом бонусов.
3. Ключи в переменные окружения, не в код. Запуск с `PAYMENT_PROVIDER=kaspi`.
4. В кабинете провайдера адрес уведомлений: `https://ВАШ-САЙТ/api/payments/webhook`.

## 5. Подключить настоящие SMS
1. Скопировать `sms/_template.js` в `sms/mobizon.js` (имя по провайдеру) и заполнить `send()`.
2. Запуск с `SMS_PROVIDER=mobizon`. Код перестанет показываться на странице.

## 6. Языки (RU / KZ / EN)
Переключатель в шапке сайта, выбор запоминается. Ссылка сразу на нужный язык: `/?lang=kk`, `/?lang=en`.
- Тексты интерфейса: `public/i18n.js` (три словаря рядом, ключи одинаковые).
- Меню, добавки, адреса: поля `name_kk`, `name_en`, `desc_kk`, `desc_en`, `address_kk`, `address_en` в `data/menu.json` и `data/locations.json`. Новую позицию добавляйте сразу с тремя названиями.
- Сообщения об ошибках сервера тоже на трёх языках (`ERR` в `server.js`).
- Экраны персонала (`/staff.html`) и владельца (`/admin.html`) тоже на трёх языках, переключатель в шапке. Названия в CSV-выгрузке остаются на русском.
- **Казахские и английские тексты нужно показать носителю на вычитку** перед запуском.

## 8. Юридические документы и согласия
- Страницы `legal.html?doc=privacy|terms|club`: Политика конфиденциальности, Публичная оферта, Правила клуба, на трёх языках. Ссылки внизу сайта. Тексты в `public/legal.js`.
- **Реквизиты организации** вписывайте в `data/company.json` (название, БИН, адрес, телефон, e-mail, место хранения данных). Пока поля пустые, в документах видны жёлтые заглушки, а вверху страницы желтое предупреждение. Когда юрист проверит тексты и поля заполнены, поставьте `"draft": false`.
- **Это шаблоны.** Их должен проверить юрист перед боевым запуском.
- **Согласия:** вход в клуб и заказ невозможны без галочки (сервер это тоже проверяет). В базе сохраняются время согласия и версия документов (`legalVersion` в `company.json`, меняйте её при правке текстов). Отдельная необязательная галочка про рекламные рассылки.
- **Удаление данных:** кнопка «Удалить мои данные» в кабинете клуба стирает аккаунт, бонусы и данные в заказах (сами заказы остаются для учёта без имени и телефона). Заказы гостей удаляются по письму на e-mail из реквизитов.
- **Где хранятся данные.** Закон Казахстана требует хранить базы персональных данных граждан на серверах в республике. Бесплатный зарубежный хостинг для показа подходит, для боевого запуска уточните у юриста и выберите хостинг в РК.

## 7. Наполнение
- Меню и цены: `data/menu.json`. Адреса и часы: `data/locations.json`. Условия клуба: `data/club.json`.
- Фото в блок «Атмосфера»: `public/img/vibe-1.jpg` … `vibe-4.jpg` (вертикальные 3:4, до 300 КБ).
- Логотип: сейчас звезда рисуется кодом. Настоящий логотип добавить в `public/` и заменить в шапке и `favicon.svg`.

## Устройство
- `server.js` сервер. `lib/db.js` база SQLite (файл `drinkstar.db`): клиенты, заказы, бонусы.
- `payments/`, `sms/` подключаемые провайдеры (`mock.js`, `demo.js` для показа, `_template.js` для боевых).
- `public/`: `index.html` сайт, `track.html` статус заказа, `staff.html` персонал, `admin.html` аналитика, `pay-mock.html` демо-оплата.
